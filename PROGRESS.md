### Phase 2 — Communication (no LiveKit — plain WebRTC mesh instead, per explicit user request)
- `backend/app/websocket/socket_manager.py`: python-socketio `AsyncServer` (asgi mode). JWT-authenticated on connect (`auth: {token}` in handshake, rejects with `ConnectionRefusedError` if invalid — reuses `decode_access_token`/`SessionLocal` directly since socket handlers aren't in FastAPI's DI chain). In-memory `rooms: {room_code: {sid: {user_id, full_name}}}`. Events: `join-room` (sends `existing-peers` to the joiner, `peer-joined` to the rest), `signal` (relays WebRTC offer/answer/ICE candidates 1:1 via `room=<target_sid>`, since python-socketio auto-joins every sid into a room named after itself), `chat-message` (broadcasts to the room), `leave-room`/`disconnect` (cleans up + emits `peer-left`)
- `backend/app/asgi.py`: `socketio.ASGIApp(sio, other_asgi_app=app)` — combined ASGI app. **Run with `uvicorn app.asgi:application`, not `app.main:app`**, or sockets won't be mounted. REST-only tests can still target `app.main.app` directly (unaffected).
- Frontend: `src/services/socket.ts` (socket.io-client wrapper, token from localStorage, `autoConnect: false`), `src/meeting/useMeetingRoom.ts` (the core hook — owns local `getUserMedia` stream, a `Record<sid, RTCPeerConnection>` mesh, remote streams, participants, chat messages, mic/camera/screen-share toggles; STUN-only via `stun:stun.l.google.com:19302`, no TURN — fine for same-network/demo use, will drop connections across restrictive NATs), `src/meeting/types.ts`
- Mesh join protocol: joiner receives `existing-peers` and initiates an offer to each; existing members just wait for that incoming offer and answer it. Avoids duplicate/glare connections without needing sid-ordering tie-breaks.
- Screen share implemented via `RTCRtpSender.replaceTrack()` (no renegotiation) — swaps the outgoing video track to the display-media track on all peer connections, auto-reverts on `track.onended`.
- UI: `src/meeting/VideoTile.tsx`, `VideoGrid.tsx`, `Toolbar.tsx` (mic/camera/share/chat/participants/leave), `ParticipantsPanel.tsx`, `src/chat/ChatPanel.tsx` — all wired into `src/pages/meeting/[roomCode].tsx`, which now calls `POST /meetings/{room_code}/join` on load and `POST /meetings/{room_code}/leave` (added `leaveMeeting` to `api.ts`) when the user clicks Leave.

### Phase 3 — AI Features (Faster Whisper STT + NLLB-200 translation, both local/free per earlier decision)
- Design: since every participant already has their own dedicated audio path (their own socket connection from Phase 2), **speaker identity comes for free from the sid** — no diarization model needed. Chunking approach: client downsamples mic audio to 16kHz mono PCM16 and streams it continuously over the socket; server accumulates a **3-second tumbling window per sid** (`AUDIO_WINDOW_BYTES = 16000*2*3`), then transcribes+translates+broadcasts that window and starts the next one from empty (no overlap). Tradeoff accepted deliberately for MVP simplicity: sentences get cut at window boundaries (confirmed in testing — "I hope you are having a great day" was split, second half dropped mid-word) and latency is ~3s+inference time, well above the README's 300-800ms target. A production version would need VAD-based variable-length chunking and overlap-stitching; noted as a known gap, not silently ignored.
- Downloaded models locally (both free, no API keys, ~1.3GB total on disk in `backend/models/`, gitignored): Faster Whisper `base` (int8, CPU) — auto-downloaded by `faster-whisper` on first use via `download_root=models/whisper`; NLLB-200 distilled-600M pre-converted to CTranslate2 int8 from `JustFrederik/nllb-200-distilled-600M-ct2-int8` on HF Hub (chosen specifically to avoid needing **torch** at all — both STT and translation run on the CTranslate2 backend; `transformers` is used only for its tokenizer classes, confirmed `import torch` still fails in the venv, i.e. genuinely not pulled in).
- `backend/app/speech/transcriber.py`: lazy-loaded singleton `WhisperModel`, `transcribe_pcm16(audio_bytes) -> (text, detected_lang)` — auto language detection (`language=None`), VAD filter on.
- `backend/app/translation/language_codes.py`: ISO 639-1 → FLORES-200 code map (`en`→`eng_Latn` etc., ~30 common languages) since UserSettings/Whisper use simple 2-letter codes but NLLB needs FLORES codes.
- `backend/app/translation/translator.py`: lazy-loaded singleton `ctranslate2.Translator` + tokenizer, `translate(text, src_iso, tgt_iso)` — returns unchanged text if src==tgt, `None` if either language isn't in the FLORES map (caller skips that target rather than crashing).
- `backend/app/websocket/socket_manager.py`: new `audio-chunk` event — appends incoming bytes to a per-sid buffer, and once the 3s window fills, resets the buffer and spawns `asyncio.create_task(_process_audio_window(...))` (so the socket handler itself never blocks). That task runs `transcribe_pcm16` via `asyncio.to_thread` (CPU-bound, must not block the event loop), looks up every current room participant's `caption_language` from `UserSettings` in one query, translates into each **unique** target language once (not once per participant), and emits a `caption` event to the whole room with `{sid, full_name, text, lang, translations: {lang: text}, ts}`. Buffers are cleared on `disconnect`/`leave-room` to avoid a slow memory leak across long sessions.
- Frontend: `src/meeting/audioCapture.ts` — `AudioContext` + `ScriptProcessorNode` (deprecated API, but simplest for MVP; `AudioWorklet` would be the production-grade replacement) taps the local mic stream, downsamples from the browser's native sample rate to 16kHz via simple block-averaging, converts to Int16 PCM, and emits `audio-chunk` continuously. Routed through a silent `GainNode` before `destination` — required in some browsers for `onaudioprocess` to fire at all, deliberately silent so the user doesn't hear their own mic echoed back.
- `useMeetingRoom.ts` now also: starts audio capture right after socket connect, listens for `caption` events (keeps last 50 in state), and exposes `captions` from the hook.
- `src/captions/CaptionOverlay.tsx`: renders the last 3 captions as an overlay (top or bottom, per the viewer's own `caption_position` setting) with speaker name, a language badge, and — per README's "toggle original/translated" requirement — shows either `caption.text` or `caption.translations[myLanguage]` depending on a toolbar-driven toggle (falls back to original if no translation exists for that pair, e.g. unsupported language). Font size also pulled from the viewer's own settings.
- `Toolbar.tsx` gained a "Captions: original / Captions: translated" button; `meeting/[roomCode].tsx` fetches the viewer's own settings via `fetchMySettings` (TanStack Query) to drive the overlay's language/position/font-size, and renders `CaptionOverlay` inside the (now `relative`-positioned) video area.
- Added `faster-whisper`, `ctranslate2`, `transformers`, `sentencepiece`, `huggingface_hub` to `backend/requirements.txt`; added `WHISPER_MODEL_SIZE`/`WHISPER_MODEL_DIR`/`NLLB_MODEL_DIR` to `settings.py` and `.env.example`.

I hope you are having a great day."), converted to 16kHz mono PCM16 with ffmpeg, confirmed `transcribe_pcm16` returns the exact correct sentence, confirmed `translate` produces correct Spanish/French, then drove two live `python-socketio` clients (Alice speaking, Bob with `caption_language=es`) — streamed the PCM in realistic ~8KB chunks over the actual socket, confirmed Bob received a `caption` event with `lang: "en"` and `translations: {"es": "Hola, ¿cómo estás hoy?"}`. ## DONE (bugfix pass, 2026-07-29, from real local testing feedback)
- **Fixed: mic/camera were effectively compulsory to join.** `useMeetingRoom.ts` `start()` had a hardcoded `getUserMedia({ video: false, audio: true })` (a leftover from local testing with no camera) instead of the intended graceful fallback. Restored the proper chain: try audio+video → fall back to audio-only → fall back to video-only → join with neither and show the error banner rather than blocking. `micOn`/`cameraOn` now initialize from what was actually acquired instead of always defaulting to `true`.
- **Fixed: sender saw their own chat message twice.** `sendChat()` in `useMeetingRoom.ts` was optimistically appending the message locally *and* the server's `chat-message` broadcast (`socket_manager.py`) already sends to the whole room including the sender (no `skip_sid`) — so the sender got it twice while everyone else correctly got it once. Removed the client-side optimistic append; the UI now relies solely on the server echo, so sender and receivers all see exactly one copy. Verified live over real sockets (see below).
- **Fixed (highest priority — translation quality): captions/translations firing on silence, background noise, and even with the mic off.** Root causes and fixes:
  1. `audioCapture.ts` was unconditionally emitting `audio-chunk` on every `onaudioprocess` tick regardless of the mic track's `enabled` state — muting the mic (`toggleMic`) never actually stopped audio capture, just relied on the browser zeroing the samples (inconsistent across browsers/situations). Now gates on `audioTrack.enabled` and skips emission entirely while muted.
  2. `transcriber.py` had no energy gate — Whisper's own `vad_filter=True` still hallucinates short phrases on quiet room tone/fan noise/mic hiss. Added an RMS energy pre-check (`MIN_RMS_ENERGY`) that skips calling Whisper at all below that threshold, plus dropped low-confidence segments (`avg_logprob < MIN_AVG_LOGPROB`), `condition_on_previous_text=False` (was letting hallucinated text bias the next window), and `no_speech_threshold=0.6`.
  3. Added ~0.5s overlap between the fixed 3s tumbling audio windows (`socket_manager.py`, `AUDIO_OVERLAP_BYTES`) so words spoken right at a window boundary aren't cut off and silently dropped — this was a real contributor to "wrong words" beyond just noise pickup.
- **Verified with a real live-socket integration test** (two `python-socketio` clients against a real running uvicorn server, not just unit calls): sent one chat message from A — both A and B received exactly 1 message each (previously A would have received 2); sent 3s of pure silence over `audio-chunk` — produced zero captions (previously this could hallucinate a caption). Also unit-verified `transcribe_pcm16` directly on silence and low-amplitude random noise: both now return `("", "")`/no text.
- Verified `npm run build` still compiles cleanly after the TS changes (removed now-unused `fullName` param from `useMeetingRoom`'s options).
- Not fully fixed, flagged as remaining risk: the 3s fixed-window approach (even with the new overlap) is still not true VAD-driven variable-length segmentation, so STT accuracy on fast speech or unusual accents may still be imperfect — the overlap and energy/confidence gating meaningfully reduce garbage output but don't guarantee perfect transcription. If translation quality is still unsatisfying after this fix, the next real lever is switching `whisper_model_size` from `base` to `small`/`medium` (slower, more accurate) or doing the full VAD-based dynamic windowing rewrite noted below.

## NOTES

- DECIDED (2026-07-28): no LiveKit for Phase 2 — explicit user request to avoid it "if possible." Used plain browser WebRTC in a full mesh topology (every participant connects directly to every other participant) signaled over Socket.IO instead. This is the right tradeoff for MVP/small meetings (no LiveKit server/API keys/SFU infra needed) but does **not** scale — mesh bandwidth/CPU grows O(n²) with participant count, workable for maybe 4-6 people max. Caption latency is ~3s+inference (worse than the README's 300-800ms target) because of the fixed window size. If this needs fixing later: add VAD (`faster-whisper`'s own VAD filter already flags speech vs silence per-segment, so the pieces exist) to decide window boundaries dynamically, and keep a small overlap between windows, re-stitching duplicate words.
- Backend `models/` directory (~1.3GB: Faster Whisper `base` + NLLB-200 distilled-600M-int8) is real, downloaded, and gitignored — not committed, but also not something a fresh clone will have; first run will need `WHISPER_MODEL_SIZE`/`NLLB_MODEL_DIR` paths to exist or the models will re-download automatically (Whisper does; NLLB in `translator.py` expects a local CTranslate2 export already in `nllb_model_dir` — currently there is **no automatic download path for the NLLB model**, only Whisper's.
